# Тренировки

Оффлайн-трекер силовых тренировок. Одностраничное PWA без сборки и без бэкенда:
всё лежит в `index.html`, данные — в `localStorage` браузера.

Открыть: **https://vitalyryzhkov.github.io/workout-tracking/**
На телефоне — «Добавить на экран «Домой»», дальше работает без сети.

## Что внутри

| Файл | Что это |
|---|---|
| `index.html` | всё приложение: разметка, стили, логика и база из 1324 упражнений (константа `LIB`, одной строкой) |
| `sw.js` | service worker: оболочка — network-first, картинки и гифки — cache-first в отдельном долговечном кэше |
| `manifest.json`, `icon-*.png` | установка на домашний экран |
| `images/`, `videos/` | превью и гифки упражнений, по 1324 файла |

## Экраны

- **Старт** — дни программы. В подходе подставляются значения с прошлой тренировки и подписаны как «было».
- **База** — 1324 упражнения с русскими названиями и описаниями. Фильтры по группе, инвентарю и по ограничениям нагрузки.
- **Дневник** — рост по каждому упражнению (первая тренировка → последняя) и список прошлых тренировок.
- **Ещё** — таймер отдыха, отсчёт «приготовься», экспорт и импорт данных в JSON.

## Ограничения нагрузки

У каждого упражнения в базе есть поля, по которым работает фильтр «⚕ Ограничения»:

| Поле | Значения | Смысл |
|---|---|---|
| `ax` | none / low / high | осевая нагрузка на позвоночник |
| `iap` | low / med / high | давление в брюшной полости (важно при ГПОД и грыжах) |
| `imp` | none / low / high | ударная нагрузка |
| `hd` | 0 / 1 | 1 — нет положения вниз головой: наклонной скамьи головой вниз, римской скамьи, висов, стоек (рефлюкс, ГПОД) |
| `sp`, `kn`, `sh` | 0 / 1 | щадит спину / колени / плечи |
| `pos` | lying / seated / standing / kneeling / unknown | положение тела |

`sp` считается строго: осевой нагрузки нет, ударной нет, давление не высокое,
и в движении нет сгибания или скручивания позвоночника под нагрузкой.
Работа на пресс и кор (`bp:waist` или `tg:abs`) исключается целиком — кроме
удержаний и антидвижений, где позвоночник как раз держат неподвижным
(планка, bird dog, dead bug, мостик, наклон таза, растяжки).

`imp` тоже пересчитывается, а не берётся из исходного датасета: прыжки часто
видны только в описании, а `sp` выводится из `imp` и молча наследовал бы ошибки.
По описанию прыжок засчитывается лишь там, где он уместен (кардио и ноги) —
иначе «приземлившись на подушечку стопы» из обычного выпада читается как прыжок.

Наклон корпуса вперёд со снарядом в руках тоже берётся из описания: в названии
он есть только у `bent-over`, а ограничение владельца — на любой такой наклон.

`ax` не зависит от инвентаря, а зависит от того, как идёт нагрузка. Жим над
головой осевой всегда — хоть штангой, хоть блоком, хоть резиной (`high`, если
снаряд лежит на теле, иначе `low`). Шраги стоя и сидя — `low`: снаряд висит в руках. Всё, что делается лёжа, —
`none`, и это правило сильнее правила про шраги. Работа предплечий и всё, где
руки лежат на упоре (сгибания запястий, скамья Скотта), — тоже `none`. Ягодичный мост под `hd`
не подпадает: голова лежит на полу, вниз головой человек не оказывается.

Классификация выведена автоматически из названий, описаний и структурных полей
(`bp`, `tg`, `eq`) и пересчитывается детерминированно: базой берутся исходные
значения из первого коммита, поверх применяются правила целиком. Правки поверх
правок не накапливаются, результат воспроизводим.

Она всё равно **ориентировочная**. Помогает отсеять явно неподходящее, но не
заменяет решение врача или физиотерапевта.

## Разработка

Сборки нет — правится `index.html` напрямую. Локально:

```bash
python -m http.server 8140
```

После правки `index.html` подними версию `CACHE` в `sw.js` (`strength-vN`),
иначе установленное приложение продолжит открывать старую копию из кэша.

Дни программы живут в `seedData()` и попадают только в новую установку.
Чтобы изменения доехали до уже установленного приложения, подними `REV`
и допиши правило в `migrate()`.

`migrate()` сверяет упражнения **по имени**: заменяет или переименовывает
только то, что называется так же, как в прошлой ревизии, и не добавляет
второй раз то, что уже есть. Если пользователь переименовал упражнение —
правило до него не доедет, и это осознанно. А вот подходы, повторы и вес
у совпавшего по имени упражнения `swap` перезапишет: заметку `rename`
бережёт (ставит только в пустую), остальное — нет.

Нормализацию и миграцию гоняет `normalizeDB()` — она вызывается и при
старте, и после импорта бэкапа, чтобы старый бэкап не откатывал программу.

Перед обновлением полезно сделать бэкап: **Ещё → Экспорт в файл (JSON)**.
